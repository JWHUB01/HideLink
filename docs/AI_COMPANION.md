# ИИ-собеседник: запасной вариант

**Статус: шов реализован, провайдер не подключён.** Владелец может включить
разрешение в `/admin`, но ни один запрос к модели не уходит: в модуле стоит
no-op провайдер, который отказывается отвечать. Так и задумано решением
`docs/DECISIONS.md` D38 §4 — «до появления провайдера переключатель хранится, но
ничего его не читает».

## Зачем это нужно

Если случайный поиск не нашёл человека, разговор может продолжить нейросеть — под
видом обычного случайного собеседника, без отдельной пометки в интерфейсе. Это
решение продукта, зафиксированное в D38 §6; риски (модель может «сломать
характер», а сервис не может честно обещать обратное) там же названы и приняты.

## Как устроен шов

| Часть | Где | Что делает |
| --- | --- | --- |
| Типы и порт | `apps/api/src/integrations/ai/ai-companion.types.ts` | `CompanionRequest`, `CompanionPayload`, интерфейс `AiCompanionProvider`, DI-токен |
| Разрешённая нагрузка | `ai-companion.payload.ts` | `buildCompanionPayload` — единственное место, где формируется объект для провайдера |
| Провайдер «нет» | `ai-companion.provider.none.ts` | `isConfigured() === false`, `composeReply` отклоняет запрос |
| Гейт | `ai-companion.service.ts` | `isAvailable()` = разрешение владельца **и** настроенный провайдер; `composeReply()` возвращает `null`, когда шов закрыт |
| Модуль | `ai-companion.module.ts` | Связывает токен с no-op провайдером; здесь же появится реальный клиент |
| Настройки | `apps/api/src/config/env.ts`, `.env.example` | `AI_COMPANION_PROVIDER`, `AI_COMPANION_BASE_URL`, `AI_COMPANION_API_KEY`, `AI_COMPANION_MODEL`, `AI_COMPANION_TIMEOUT_MS` |

Два ключа, а не один: переключатель в `/admin` — это *разрешение*, а настроенный
провайдер — *возможность*. Ни одного из них недостаточно по отдельности, и
переключатель перечитывается при каждом вызове, так что выключение в кабинете
действует сразу.

## Что видит провайдер

Только `CompanionPayload`:

- `persona`: пол, возрастные границы, страны, регионы, города, языки и
  `relaxAllowed` — те фильтры, которые реально применяются сейчас;
- `language` — язык интерфейса, если известен;
- `relaxationSteps` — сколько фильтров сервер уже снял.

Чего в типе нет и что поэтому нельзя отправить случайно: User ID, токен сессии,
блокировки, друзья, жалобы, архив переписки, IP/User-Agent-хеши. Список полей
явный, а не «всё, кроме»: новое поле в фильтрах не попадёт в модель, пока его не
добавят в `buildCompanionPayload` осознанно. Это проверяет
`apps/api/test/ai-companion.test.ts`.

## Чего ещё нет (и что нужно до включения)

1. **HTTP-клиент провайдера.** Сегодня в реестре только `none`. Новый провайдер =
   новое значение `AI_COMPANION_PROVIDER`, реализация `AiCompanionProvider` и
   регистрация в `AiCompanionModule`.
2. **Решение о моменте срабатывания.** D38 §4 оставляет за адаптером: сколько
   ждать, до или после расширения фильтров, и как не отнять место у живого
   кандидата. Сейчас в домене чата нет ни одного вызова шва — и это правильно:
   показывать нечего.
3. **Серверная метка «это ИИ».** Для модерации, хранения и разбора жалоб сервер
   должен отличать компаньона от человека. Метка не выходит в `ChatView`, протокол
   или DOM (D38 §6); в схеме БД её пока нет — это отдельная миграция.
4. **Хранение и раскрытие.** D38 требует отдельного решения о сроке хранения
   переписки с ИИ и о том, что интерфейс остаётся молчаливым. До этого включать
   нельзя.
5. **Бюджет и лимиты.** Стоимость одного разговора, потолок на пользователя в
   минуту/сутки, таймауты и поведение при ошибке провайдера (возврат в очередь, а
   не зависание).
6. **Проверка персоны.** Если модель не может соблюсти активные фильтры, D38
   требует fail closed: чат не создаётся.

## Настройки

```dotenv
# По умолчанию шов выключен: провайдер не выбран.
AI_COMPANION_PROVIDER="none"
# AI_COMPANION_BASE_URL="https://api.example.com/v1"
# AI_COMPANION_API_KEY=""
# AI_COMPANION_MODEL=""
# AI_COMPANION_TIMEOUT_MS=12000
```

Ключ провайдера — серверный секрет: он не попадает ни в веб-сборку, ни в протокол.

## Проверка

```powershell
pnpm --filter @anonlink/api exec vitest run test/ai-companion.test.ts
```

Тесты подтверждают: нагрузка содержит только разрешённые поля, массивы
копируются, без настроенного провайдера сервис недоступен даже при включённом
переключателе, а no-op провайдер не придумывает текст.
